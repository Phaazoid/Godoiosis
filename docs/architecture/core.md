## Registries

Registries: `Classes/core/Stats.gd` (`STAT_DEFAULTS` is the canonical stat list — input stats STR/DEX/PER/CON; missing dict keys read defaults, never 0; also home of the stat-shadow doctrine: `*_band` helpers + `armor_def`, pure statics per `docs/design/stats.md`; and since #485 the scaling vocabulary — **`SCALING_STATS`** (the four a weapon attack's blend may use, which `weapons.md` had asserted in prose since the blend was written while no code declared it, so the reflective editor drew all eight including MHP and WIL), **`BLEND_TOTAL`**, and **`blend_text`**, the one renderer that NORMALISES before printing, because raw weights are not percentages), `Classes/weapons/WeaponCatalog.gd`, `Classes/items/ArmorCatalog.gd` (#65, 2026-07-24: flat disk-scan over `Resources/Armor/` — armor has no template/instance split yet, so a catalog entry IS the equippable, unlike weapons; the model it scans grew teeth in [#89](https://github.com/Phaazoid/Godoiosis/issues/89) — see [`docs/build-log.md`](../build-log.md) → *Armor*), `Classes/units/UnitCatalog.gd` (#177 — the cast: standalone `UnitData` character files under `Resources/Units/`; read by the SpawnTool's Character dropdown, and the files it serves are what authored saves reference), `Classes/jobs/JobCatalog.gd` (scan cached per-session since 2026-07-22 — a runtime job-authoring tool must call `refresh()` after saving; `ReactionCatalog` and `TerrainReactionCatalog` cache the same way since [#1213](https://github.com/Phaazoid/Godoiosis/issues/1213), being every resolve's default arguments, and the Tiles page's burnable tick is their one runtime writer, refreshing first; the other catalogs still scan per call, safe only outside hot paths), `Classes/jobs/Abilities.gd` (#61: the `Id` enum + tuning-constant registry every ability hook reads from). Rule: game content lists → domain-named registry; single-system config → stays local.

## The core/ folder: Glossary, Pacing, PlayerSettings, Controls

`core/` — cross-cutting vocabulary used everywhere: `Stats`, `GridUtils`, `Glossary` (#135 — the ONE term registry: every player-facing term at two lengths, `short` = the hover tooltip every surface reads (main-menu rows, stat rows, state icons, the tile card, whose zone terms live on a Missions page since #1105), `long_text` = the GlossaryScreen page body. Numbers are interpolated from the constants that rule them, never retyped, and the elemental/terrain interaction lines are COMPOSED from the live reaction catalogs — hand-authoring one is the drift the design forbids. Completeness and the `Stats.Stat`/`Terrain.TileState`/`Elemental.State` bridges are pinned by `tests/law/test_glossary_coverage.gd`, so a new stat or state cannot ship without its entry); also `Pacing` (#118 — the one declared table of playback pauses -- five constants at #118, seventy-odd by 2026-08-29 as the beat table (#519), the tear-out and its held beats (#521), the LINGER, the flourish channel (#520 diff 2b), lethality-aware direction (2c) and the cliff follow (#602) landed, plus `beat(host, seconds)` that every pause routes through -- and since 2c a SECOND pause primitive, `hitstop(host, seconds)`, which spends its time by setting `Engine.time_scale` to 0 rather than by waiting. Its unfreeze timer is created with `ignore_time_scale` or it would be frozen by its own freeze and hang the game; re-entry is COUNTED so two deaths in one volley cannot race two restores; and it carries the same headless escape for the same reason. Since [#545](https://github.com/Phaazoid/Godoiosis/issues/545) every playback escape asks `Pacing.unwatched()` (headless, or a skip resolving under its fade) and `_apply_time_scale` is the one writer of `Engine.time_scale`, so a freeze returns to the playback speed rather than to 1.0.

**Its headless escape is a safety property**: `OrderExecutor.execute_orders` is awaited by 34 test call sites across 12 suites (measured 2026-08-27), so a literal timer at an await site puts real wall clock on every case that resolves a plan. `CameraController.pan_to` carries the same escape and snaps instead of tweening — `tests/ai` went 19.0s → 7.5s on that alone — and since 2026-08-26 the `_process` glide lands headless too (the last watched-pacing glide without the escape, found when a dev-tree case sampled a hover cell off the mid-glide camera and was red ONLY on CI; `tests/ui/test_camera_glide.gd` pins it). Tuning any of them must never turn the suite red, so **no test asserts what any value is** (dev, 2026-08-10); `tests/core/test_pacing.gd` pins only the zero-frames-headless property. Law #2 is untouched — execution is pure playback of an already-resolved plan (R3), so a beat changes only *when* frames land.

**`beat()` is also THE PAUSE POINT since [#723](https://github.com/Phaazoid/Godoiosis/issues/723) (2026-09-07)**, Esc now opening the pause menu during an AI turn: it parks while `ModalLock.any_open` and resumes where it left off. **`ModalLock` is not enough on its own, and the reason is measured** — it disables the GAME NODE rather than pausing the tree (deliberately, see its header), while every wait here is a `SceneTreeTimer` owned by the tree with `process_always`, so the freeze stops `_process` loops and has never stopped a coroutine. The park sits **ABOVE the headless escape**, which is a correctness requirement rather than tidiness: everything past that line is invisible to a headless suite, so a park written below it could not be tested and a mutant deleting it would pass (#506's shape). Only `beat()`, not `hitstop()` — a hitstop is a fraction of a second on `ignore_time_scale`). Also `PlayerSettings` ([#350](https://github.com/Phaazoid/Godoiosis/issues/350) — the ONE store for preferences a PERSON chooses and keeps, as against a mission's authored look, a dev experiment or a tuning value: `enum Setting` + a `DEFS` table (title/desc/default, plus `options` on a CHOICE row or `min`/`max`/`step` on a LEVEL one) + `ConfigFile` at `user://settings.cfg` keyed by the member NAME. `Experiments`'s shape minus its cull-the-flags doctrine, because a setting is a promise to the player; a static class, no autoload, and callers poll it rather than a changed signal.

**A HEADLESS PROCESS HONOURS NOBODY'S PREFERENCES ([#449](https://github.com/Phaazoid/Godoiosis/issues/449)): `_static_init` clears `persistence_enabled` when `DisplayServer.get_name() == "headless"`, so the suite and the Play API read DEFAULTS and cannot inherit the machine's own cfg** — `Pacing.beat`'s spelling of *nobody is watching*, applied to `Experiments` in the same diff. It replaces a per-suite `reset_for_test()` discipline nothing could enforce: **22 suites instantiate the real board and not one called it**, and what noticed was a presentation case that passed or failed by whatever the dev had switched on while playtesting — taking the nine cases after it out of the run with no sign that it had. `reset_for_test()` keeps its *other* job (wiping a value a suite SET — `_state` is a static that outlives a case), and a suite wanting the real disk path opts back in by setting `persistence_enabled = true` itself, as the round-trip case does.

**Residual: a gdUnit4 run driven from the EDITOR panel is not headless**, so a suite asserting on a setting-driven surface still declares which branch it is in out loud. `SettingsScreen` is a pure projection of `DEFS`, which is the point of paying for a table with one row in it: [#217](https://github.com/Phaazoid/Godoiosis/issues/217)'s photosensitivity toggle became a store edit rather than UI work. **FOUR ROW KINDS — two since [#418](https://github.com/Phaazoid/Godoiosis/issues/418), a third since [#136](https://github.com/Phaazoid/Godoiosis/issues/136), a fourth since [#1049](https://github.com/Phaazoid/Godoiosis/issues/1049)** — a row is a toggle unless it declares `options`, in which case it is a CHOICE, or `step`, in which case it is a LEVEL the player slides, or `max_length`, in which case it is TEXT the player types; the KIND is derived from the table rather than stated in a second field.

**The TEXT row's three traps are each the level row's one kind along, and all three are the same shape — a value that is not a bool coerced by something that assumes one.** `load_state` answers TEXT before the toggle fallback, whose `bool()` reads a saved name back as `true`; `is_on`/`set_on` refuse a text row, because `bool("")` is false and `bool("Jae")` is true, so an unnamed player would read as OFF and a named one as ON, plausibly, forever; and **a text row is cleaned on BOTH sides** (this line used to say trimmed at read and never at write, which the code had stopped doing: `set_text` stores `_clean_text`'s answer, and that trims), so `SettingsScreen`'s per-frame reconcile would rewrite the box under the caret and make a two-word name untypeable. That is why the reconcile is the page's one exception to *controls follow the store*: it skips a `LineEdit` that `has_focus()`, and `focus_exited` puts the stored value back, so the exemption lasts exactly as long as the typing does.

**A row at its DEFAULT is never stored ([#648](https://github.com/Phaazoid/Godoiosis/issues/648), dev ruling 2026-10-09):** `set_value` erases the key instead of writing today's default in, and `load_state` drops one an older cfg holds, because absence is what follows the default, and a player who put a setting back where they found it would otherwise be pinned to it and never see the next default. A level counts as its default to float precision (`is_equal_approx`), since a slider hands back `k * step` and `12 * 0.05` is not `0.6`. **A LEVEL's bounds are FLAT keys (`min`/`max`/`step`), never a nested dict** — `DEFS` is a const literal and `KnobSource`'s `SETTING_DEFAULT` rewriter is brace-bounded per entry, so the first nested `{}` in that table would break a save it cannot see coming. `SFX_VOLUME` is the first and pays for the kind, **`MUSIC_VOLUME` the second (#136 slice 3) — its own row rather than a share of the first, because the two buses are SIBLINGS sending to Master, so the effects slider moves nothing on music and shipping a score without this ships one the player cannot turn down**; `level_of`/`set_level` are its façades, and **`load_state` answers a level BEFORE the toggle branch**, whose `bool()` would read every saved volume back as `true` — #647's coercion trap from the persistence side, pinned by `test_a_level_survives_a_relaunch_as_a_NUMBER`. The projection survives because the page learns a row's kind, never its NAME. Generic `value_of`/`set_value`/`default_value` are what a caller walking `DEFS` uses; `is_on`/`set_on` and `choice_of`/`set_choice` are typed façades over them.

**Each façade REFUSES the other kind's row since [#647](https://github.com/Phaazoid/Godoiosis/issues/647)**, because the coercions underneath are silent and the damage is not: `bool(1)` and `bool(2)` are both true, so a caller left on `is_on` after a row became a choice reads every non-zero option as ON, and `set_on` writes a BOOL into a choice row that `choice_of` reads back as `int(true)` = 1 and `load_state` re-reads the same way — the wrong value surviving a relaunch, consistently wrong. #418's own conversion escaped that only by RENAMING its setting (and #647 renamed `BATTLE_ZOOM` to `BATTLE_ZOOM_MODE` for the same reason), i.e. by remembering to; the guard means the next one refuses on its own. The WRITERS refuse outright rather than degrade — a bad read is one wrong frame, a bad write is a cfg the player carries between sessions.

**A control on BOTH a dev and a player surface polls the store rather than latching it** (dev, 2026-08-28: they may never disagree) — see `docs/design/presentation-effects.md` → *One value, one store*. **A third tenant of the CHOICE kind landed in [#422](https://github.com/Phaazoid/Godoiosis/issues/422) (2026-09-01), `AIM_PALETTE`, and what it is worth remembering for is what it did NOT need**: the ask was free per-colour reticule pickers, i.e. a third row kind plus a game-side colour widget; asking the player to pick a named PALETTE instead made it an ordinary choice row, no new widget, and a better answer to the colour-blindness want underneath (a palette is designed as a SET, where four freely picked colours can be chosen into a combination nothing reads against). It is also NOT a *one value, one store* case -- the dev authors what is in a palette, the player picks between palettes, which is the different-AXES case one section up in `presentation-effects.md`.

**Which of the two a value belongs to is worth re-asking at build time rather than inheriting from how the ticket was filed** -- that doc had predicted this one would move its home, and it does not. **[#394](https://github.com/Phaazoid/Godoiosis/issues/394) (2026-09-01) added the store's FIFTH-to-SEVENTH choice rows and a THIRD relationship to go with them.** Its `unhovered_shows_number` half is the ordinary #422 case -- dev and player on the same axis, so the value MOVES: the `@export` left `UnitMirror`, the `KNOBS` row left the table, and the Game tab shows it as a `CLASS_KNOBS` row bearing a `"setting"` key, which writes the real preference and polls it. *(Corrected 2026-10-20: the value now lives at `PlayerSettings.Setting.UNHOVERED_BAR_NUMBERS`.)* That is also what finally exercised the DEFS-literal save `presentation-effects.md` had named since #422: **`KnobSource.Kind.SETTING_DEFAULT`**, whose regex is bounded to one entry's own braces so a row that has lost its `"default"` FAILS rather than rewriting a sibling's.

**Its camera half is the third relationship and the more reusable one: the player SCALES what the dev authored** (`PlayerSettings.Scale` over three rows, `CameraRig3D.SCALE_FACTORS` with `NORMAL` absent and falling through to 1.0), so nothing leaves `GameKnobs`, Save is untouched, and -- unlike a palette -- **no knob is ever inert**, which is the reason to reach for a multiplier first. Canon: `presentation-effects.md` -> *The player SCALES what the dev authored*. **A choice row is a segmented strip of toggle Buttons in one `ButtonGroup`, never an `OptionButton`** — a dropdown opens an embedded `PopupMenu`, which does not dismiss on outside-click inside `GameView` (sharp edge: the SubViewport gotchas, the #26 reason the action menu is Control-based); `ReportForm._build_kind_row` is the same shape.) Also `Controls` ([#690](https://github.com/Phaazoid/Godoiosis/issues/690) — the ONE binding registry: every key and gesture, its context, the mode it needs, what it does, and the Input Map action it fires or `HARDCODED`. `Glossary`'s shape, and in `core/` for the same reason — it is not dev-only: the dev Info tab projects its DEV context today and [#691](https://github.com/Phaazoid/Godoiosis/issues/691)'s Settings Controls tab takes the player-facing ones, filtered by that field, with rebinding gated on the action half. It REPLACED a hand-maintained markdown table, and the point of paying for a registry is that `tests/law/test_controls_coverage.gd` walks it against the live Input Map both ways — a documented action that no longer exists, and an action nobody documented, each red. Since [#1368](https://github.com/Phaazoid/Godoiosis/issues/1368) it also refuses one press bound twice where both `when`s are AMBIENT (`""` or a view): V had been the enemy ranges and the dev selector depth at once, hidden from the old duplicate check by a different context and `when`. A binding behind a MODE `when` is trusted to take the press from the ambient one, which is code the registry cannot see.

**#691 (2026-09-02) filled the PLAYER contexts and DELETED `docs/SHORTCUTS.md` outright** -- every section of it now has a home, and the registry is the one answer for a binding across both audiences. Its contexts split by what the player is DOING (BOARD / CAMERA), deliberately not by view: F4 is `DevTools.enabled()`-gated, so a shipped build has no flat 2D view, and a page headed "the flat 2D game" would document a screen the player cannot open. `PLAYER_CONTEXTS` is the declared filter the Settings page reads, so a second dev-only context cannot publish itself. With both audiences covered the law went to its strong form: EVERY Input Map action that is not a `ui_` built-in must be documented.)
