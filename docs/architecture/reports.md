## BugReporter

**`BugReporter` (#128, made player-facing by #131 on 2026-08-05) is the report system**, no longer a dev-only dump despite still living in `Classes/dev/`: it writes `user://reports/<stamp>/` — `board.tres` (authoritative) + `report.md` (a read-only PROJECTION: the player's note, game state, the queued plan, a unit index, the log tail, and since [#240](https://github.com/Phaazoid/Godoiosis/issues/240) the **view and look it was seen under** — hosting mode, camera yaw, zoom and centred cell, pushed in by `battle3d._ready` on the `attach_3d_host` idiom, plus the board's own `ScenarioManager.current_look_preset`; an unhosted `Main.tscn` launch says so rather than leaving a blank, **plus which DEV TAB was up ([#328](https://github.com/Phaazoid/Godoiosis/issues/328))**) + `board.png` + **`devtools.png`, written only while the dev-tools window is open (#328)** + **`camera.png` and a `## Camera recording` section, only when the dev recorded key poses (#705)** — and then ships the folder. It is a game collaborator on the `DevController` pattern and **owns no seam of its own** — the board is `ScenarioManager.capture_scenario` (#87), the plan is `ActionQueueDisplayEntry.build_for` (what the queue panel draws, so the dump shows what the player saw), the numbers come off `action.resolved`, "recent log" is a tail of Godot's own `user://logs/godot.log` rather than a second battle log ([#119](https://github.com/Phaazoid/Godoiosis/issues/119) owns that) — **that path is verified correct but its FLUSH behaviour in an exported build is not**: the engine's file logger buffers and a release build flushes less eagerly than a debug one, so the tail may be short of exactly the lines a report wanted. If a real build's reports come back with a thin or empty log section, that is the cause and not a broken read (open question at #131's close, 2026-08-05; also the reason a report's own `push_error` calls are worth keeping loud), and the transport is `ReportUploader`, which is handed a directory and never looks inside one.

**NOTHING IT SHIPS NAMES THE MACHINE IT CAME FROM ([#1036](https://github.com/Phaazoid/Godoiosis/issues/1036), 2026-09-19).** `build_report_text` and `build_summary` both return through `BugReporter.scrub_paths` — the user data dir rewritten to `user://`, then the home dir to `~`, each in both slash forms and case-insensitively, because Windows prints a path either way. **The ORDER is the guarantee:** the data dir lives INSIDE the home dir, so what pass 1 misses — a bare mention, with no separator after it, pass 1 taking the separator because `get_user_data_dir()` carries none while a globalized path does — falls through to pass 2 as `~/AppData/.../Iosis`, which names no account either. It is enforced at those two builders rather than at each `print` because the body carries the tail of an engine log this project does not author; the one line that DID author a leak was this file's own *"Report written to"*, which globalized the folder into `godot.log` for the NEXT report's tail to ship — measured, all five retained session logs held zero engine-produced absolute paths and only that print. Deliberately NOT at `Uploader.submit`, the literal reading of *everything shipped*: the summary is `JSON.stringify`'d before it gets there, so a backslash path arrives escaped and the match would silently miss. `Checkout.describe()` needs no scrub and that is **structural** — it builds its answer out of `HEAD`'s contents and the globalized root only ever LOCATES `.git`. Two deliberate non-copies: attack rows print the **raw** `target_hp_after` because the panel's clamp-to-0/1 ladder belongs to `LethalityRules`, and `report()` **resolves without validating** — a dump reads state, it must never rewrite `is_valid`. Reports live OUTSIDE `Scenarios/` so Mission Select and `_collect_scenarios` never see them (the old `res://bug-reports/` tree and its `.gdignore` are now vestigial — **`res://` is read-only once exported**, which is what made the whole feature inert in a build and forced the move).

## Kind: BUG or FEEDBACK

**`Kind { BUG, FEEDBACK }` is the ONLY fork between "what broke" and "what did you think"** — same folder, same files, same transport, same code path, only the prompt and the label differ. #131 item 6 asked for feedback not to "ride the bug-report path"; what actually has to be distinct is the QUESTION, and two transports for one act would be a second seam for a fact one field already carries.

## BugReporter.open_card is the one funnel for a card

**`BugReporter.open_card(state_name, kind, frame)` is the one funnel for a CARD**, and all THREE card doors go through it: the `PauseMenu.Choice.REPORT` row, `MissionSelectScreen.feedback_chosen`, and **plain F3 ([#1050](https://github.com/Phaazoid/Godoiosis/issues/1050))** -- which is the one the HUD now NAMES. **A FOURTH surface hosts the form itself ([#1052](https://github.com/Phaazoid/Godoiosis/issues/1052))**: the mission-end banner carries a `ReportForm` under its verdict, starting on FEEDBACK, and hands it to `BugReporter.serve` through `game.serve_report_form` -- `serve` being the collect, send and outcome exchange `open_card` also runs, so the one path from a note to a filed report is `serve` and `open_card` is the card door onto it.

**[#1051](https://github.com/Phaazoid/Godoiosis/issues/1051) is a SIGN, not a door**: it shipped as a clickable mark and the dev ruled that the wrong answer the same day (*"I didn't want an actual report button on the screen. I wanted a notice... Now there are 3 paths to the report, and the player has no way of knowing the easiest one"*), so a fourth surface became a label naming the cheapest of the three. It reads its key through `Controls.key_for_action`, never spells one, so it cannot advertise a binding the Input Map has not got; and it lives in `MissionStatusPanel` rather than a scene of its own because that panel already owns the top-right strip -- a second node reaching into that band needed a constant restating where the version stamp ends, which is Law #4 in miniature.

**Shift+F3 is the one door that skips the card** — the dev's note-less instant report, still `DevTools.enabled()`-gated in `DevController`, because a stranger's NOTE is the whole value of their report while the dev only wants the board state. The two keys are one physical key forked by a modifier, which is why `game.gd`'s player check passes `exact_match` — `is_action_pressed` ignores additional modifiers by default, so without it a Shift+F3 press fires both paths at once. **Esc was a fourth until [#723](https://github.com/Phaazoid/Godoiosis/issues/723) (2026-09-07) and is not a door any more** — it opened the card wherever `_board_locked_for_player()` was true, which is FOUR situations rather than the three that branch's comment named (the title screen, the pre-mission screen, a finished board being inspected, and an AI turn), and it now opens the pause menu in all of them but the title screen. Nothing lost a way in: the card's Kind toggle means the title screen's FEEDBACK-defaulted button still files a bug. The reason it is a funnel and not four call sites: **the screenshot has to be grabbed BEFORE the card draws**, or the report contains a picture of the report panel. `_open_pause_menu` grabs its frame at Esc time and passes it down, and `_end_mission` grabs one before the banner draws (#1052); everyone else lets `capture_frame()` take one.

## The screenshot comes from the root viewport

**The screenshot comes from the ROOT viewport, never `game.get_viewport()` ([#240](https://github.com/Phaazoid/Godoiosis/issues/240), 2026-08-15).** `BugReporter.capture_viewport()` is that one answer, and it takes no fork on `Battle3D.view` **because there isn't one**: the root Window viewport is the composited frame in every hosting mode by construction — HD_2D draws the 2D UI over the diorama, FLAT_2D covers the window opaquely, CORNER adds the PiP, `demo_mode` hides the container, and a bare `Main.tscn` launch fills the window with the 2D game. `game.get_viewport()` was only ever wrong because `game` sits INSIDE the SubViewport, and since #222 that viewport is transparent with the board visuals hidden — so every report shipped 2D UI on nothing, with the diorama and every visual bug in it missing. Do not reintroduce a per-view branch here; pinned by `test_the_screenshot_comes_from_the_window_and_not_the_hidden_subviewport`, whose `is_not_same` half is the one that reds.

## The dev-tools window is a second file

**The dev-tools window is a SECOND FILE, never a fork of the first ([#328](https://github.com/Phaazoid/Godoiosis/issues/328), 2026-08-16).** It is a real second OS window (project `embed_subwindows` off), so it is not in the composited root frame *by construction* — the one thing #240's ruling structurally cannot show. `devtools.png` therefore costs one line in `ReportUploader.ATTACHMENTS` and no branch inside `capture_viewport()`. **`BugReporter.devtools_panel()` is the one gate** — null in a demo build (`game.dev_overlay` is null without `DevTools.enabled()`) and null while the window is closed — read by BOTH the picture and the `Dev tools:` line in `report.md`, so the two can never disagree about whether it was up. The line names the tree leaf only ("Scope / Leaf", `DevOverlay.current_tab_title()`, the window's own answer) and never promises `devtools.png`: a picture of a second OS window can fail where a line cannot, and the tab name also outlives Discord's CDN expiry. `capture_devtools_frame()` carries the same headless escape as `capture_frame()`, for the same permanent-hang reason.

## capture_frame() returns null in a headless run

**`capture_frame()` returns null in a headless run** — `RenderingServer.frame_post_draw` never fires there, so awaiting it hangs forever rather than merely slowly, with a card already on screen. A report with no screenshot is a supported outcome (`ReportUploader` skips a file that isn't there), so this degrades instead of blocking.
