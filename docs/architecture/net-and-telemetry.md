## The net/ folder

`net/` — the only outbound-network code in the project (#131, widened by [#53](https://github.com/Phaazoid/Godoiosis/issues/53) slice 5): **`Uploader` is the one pipe for what the game SENDS** — `ENDPOINT`, `PROCESS_MODE_ALWAYS`, `is_configured()`, and `submit(route, fields, files)` — with `ReportUploader` (a report folder, relayed to Discord) and `TelemetryUploader` (a sealed playtest run, into D1) as its two subclasses. `VersionCheck` (#1060) is deliberately not one: it makes its own GET and shares only `Uploader.ENDPOINT`, with a headless guard of its own. **A subclass that overrides `_ready` MUST call `super()`**, or its upload freezes behind whichever modal is up. **`is_configured()` refuses a headless run outright**, and that is a safety property, not a convenience: `ENDPOINT` is a LIVE Worker in the committed source, so without it the suite would POST on every green run — measured, two per `tests/ui` pass — and the first symptom would be the intake filling up. Pinned by a `test_a_headless_run_never_uploads` in each of `tests/ui/test_report_flow.gd` and `tests/telemetry/test_telemetry_upload.gd`. `ENDPOINT` empty is the other way to disable it, and is not a secret either way: it is an address, and the Discord token it relays to lives in a Worker secret. `MultipartForm` (a static body builder — Godot ships no form encoder, and the body **must** be a `PackedByteArray` or the PNG is silently destroyed by a UTF-8 round-trip) builds every body.

**The server half lives in `tools/intake-worker/`** (renamed from `report-worker/` when it gained a second tenant), which `export_presets.cfg` excludes: it **routes on PATH before anything else** — `""` is the Discord relay, `/telemetry` the run intake, and an unmatched path is a **404 rather than a fall-through**, since Cloudflare normalizes doubled slashes and nothing else, so `/telemetry/` would otherwise have been posted to Discord as a bug report. The telemetry row is one `summary` blob with every indexed column `GENERATED ALWAYS AS (json_extract(...)) VIRTUAL` over it, so an index cannot disagree with the record (Law #4); its caps are **D1's 2 MB per ROW** (summary + events + board share one) and **the free plan's 10 ms CPU**, which is why the Worker parses only the small summary field and stores the events verbatim.

## The telemetry/ folder

`telemetry/` — the playtest record ([#53](https://github.com/Phaazoid/Godoiosis/issues/53), arc COMPLETE 2026-09-09; canon [`docs/design/playtest-telemetry.md`](../design/playtest-telemetry.md) — **read it before touching a recorder, a metric, a replay or the intake**). `MissionLog` (the recorder, a game collaborator on the `DevController` pattern, **owns no rule**), `MissionSummary` (`of(events)` — a PURE PROJECTION, so #200's metric table and the log structurally cannot disagree), `TelemetryStore` (the paths, the anonymous install id and which notice VERSION this install has acknowledged, on `PlayerSettings`' persistence idiom so a headless run writes nothing), `ReplayRun`/`ReplayDriver` (the dev-tools diff harness), `TelemetryUploader`. **A run is a FOLDER** — `events.jsonl` + `board.tres` — and **its PARENT folder is its state**: `pending/` means still owed to the server, `sent/` means delivered and kept so the Replay tab can still open it, and `held/` ([#852](https://github.com/Phaazoid/Godoiosis/issues/852)) means sealed and NEVER going to be sent -- a pre-`run_id` run or an #851-refused empty one, moved there by `TelemetryUploader.hold_unsendable` ahead of the endpoint gate, so `pending/` means only *owed* (it had been holding 101 never-sendable runs to 1 owed on the dev's machine); a move rather than a marker, so nothing can disagree about where a run is, and `run_dir()` resolves between them.

**An UNSEALED file IS the quit record** — Alt-F4, a crash, F2 and a board swap all leave one, and `sweep_unsealed()` at launch finishes it as CRASHED, so every door is covered by one rule instead of a hook per door. **The one property the whole design protects is that a NEW QUESTION IS A QUERY, not a new build and a new cohort of players** — which is why the client computes no counters, why the raw events are stored verbatim beside the summary derived from them, and why the dev's own play is FLAGGED (`sandbox`/`dev_mode`) rather than dropped: *an exclusion destroys the evidence that the exclusion was right; a flag is a WHERE clause you can drop later* (dev, 2026-09-08).

**That law has exactly ONE exception and it is drawn where there is nothing to lose ([#851](https://github.com/Phaazoid/Godoiosis/issues/851)): the client refuses a run with no resolved pass AND no queued order, and only when somebody CHOSE the ending (`ABANDONED`/`RESTARTED`/`QUIT`/`INTERRUPTED`, the last being the main door out -- `MissionController.reset()` behind F2, a board swap, Load Game and Mission Select). A `CRASHED` run is NEVER refused however empty it is -- the only ending whose emptiness might be the story is the one nobody chose.** Everything merely THIN is sent and flagged `trivial`, which is a `GENERATED ... VIRTUAL` column rather than a stamp the client writes, so the threshold is re-cut across every run ever collected by one `ALTER` with no new build and no re-upload -- a client-side stamp could never reach a row already uploaded. Two traps worth carrying out of it: **an id written down for a LATER PROCESS must be a stable VALUE, never a runtime handle** (`_ref` wrote `get_instance_id()` and made every recorded reference unreadable; the cure was a fact the record already carried — each unit's starting CELL, `spawn_unit` refusing an occupied one), and **the recorded `turn_start` vitals are PRE-TICK**, because `MissionLog` is built in `_build_collaborators` and so connects ahead of `game._on_turn_started` — comparing one against a live board read after a hand-over cries wolf on nearly every run.
