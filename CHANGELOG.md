# Iosis release notes

One entry per build that went out, newest first. A build is a version `tools/archive-build.ps1` tagged; the version numbers between two entries were merges that never became builds. Builds handed out before v0.188.4 carried no tag and are not recorded here.

The game reads this file (#1075). The lines directly under a release heading are shown to players on the title screen's "What's new" card, so they are written for a player: one plain `- ` bullet per line, no formatting, no issue numbers. Everything from `### Internal` down to the next release is for us and never shown. `tests/core/test_release_notes.gd` lints both rules on every PR that touches this file.

Cutting a release:

1. Open a PR that adds the new entry at the top, headed `## v<version>`, where the version is main's with the last digit plus one. Leave it unlabelled: a `type/feature` label bumps the middle digit instead, and the heading would name a build that never exists.
2. Rewrite the player lines in review, merge it last, then run `tools/archive-build.ps1`. It refuses to build a version this file has no heading for.
3. If something else merged first, the version has moved on and the build refuses. Fix the heading directly on main, since another PR would bump the version again, and run it again.

## v0.205.1 (2026-09-23)

- The title screen has a What's new card listing what changed since the last build you played.
- Wet units drip and splash. Chilled units frost over, shed cold mist and breathe frost.
- Squads are drawn with lines: a dashed orange outline marks the squad's range, and a tether runs from each member to its leader.
- Hovering a squad leader greys out the tiles the squad can't follow to, the same as when you pick its move.
- Squad Up works from the leader and stays open until nobody else can join.
- A swing aimed at one target stops at the first unit it reaches. Overwatch hits one target, not everyone in its area.
- While aiming, the attack's tiles flash in the order the attack reaches them.
- The movement grid runs to the edge of each tile, so a range reads as one area.

### Internal

- Release notes: this file, the title screen's What's new card, and archive-build's release gate (#1075, PR #1076).
- Attack geometry, slices A to C of #1054. Swing became a modifier, so a true AoE is authorable (#1055, PR #1062). A shape carries paths authored on the grid (#1056, PR #1077), and is painted tiles or paths, never both (#1079, PR #1080). Single-target swings resolve along their paths and every overwatch shot hits one target (#1057 part 1, PR #1091, closing #1040). Aim footprints flash in travel order and the shape plate draws paths (#1057 part 2, PR #1097). Slice D, payloads (#1058), is still open.
- Squad markup: tethers, a marching cohesion outline, grey out-of-range tiles, a refused click that shakes its tether, and Squad Up from the leader (#1070, PR #1093; also closes #1043 and #1041).
- Wet and Chilled worn on the 3D unit sprite (#358 slice 1, PR #1096) and spilling into the world as drips, splash, mist and breath (#358 slice 2, PR #1098). The damp blot is the next PR.
- The movement grid is generated by MoveGrid from Game-tab knobs, the Game tab is grouped by subject, and pinned flashes run in step (#1074, PR #1078).
- Tuning on the move grid, overlays, threat lines and unit visuals, committed straight to main (37a4f51, 84dc9d8).

## v0.194.1 (2026-09-21)

- The report button is gone from the battle screen. A note in the top corner says F3 opens the bug report.
- Range colours were redone. Your unit's move range is a blue grid with red for where it can attack, and an enemy's whole range is one purple area.
- Clicking a carried weapon in the inventory opens its menu again.

### Internal

- The report mark became a sign rather than a button, after the dev's play of the v0.192.0 version (#1051, PR #1067).
- Range layers took Fire Emblem's colours (#1066, PR #1068) and its grammar: the move range as gridlines, and reach grown from one cell (#1069, PR #1071).
- A carried weapon's inventory popup aborted before it was built, so no weapon opened one (#1072, PR #1073).
- Tagged the day before this file existed. The #1075 backfill stopped at v0.192.0 and missed it, so it was added in the v0.205.1 release PR.

## v0.192.0 (2026-09-20)

- F3 opens the bug report card from anywhere in the game. It used to do nothing outside development builds.
- There is a report button on screen during battles, so you don't need to know the key or find the pause menu.
- Enemy threat marks start at the enemy's body instead of over its head, curve slightly, and end in a narrow cone instead of an arrowhead.

### Internal

- F3 promoted from a dev key to a player binding (#1050) and the on-screen report mark (#1051), both in PR #1065.
- The threat mark reshaped after the dev's play of #1042's first pass (#1059, PR #1061).

## v0.191.0 (2026-09-20)

- The first-launch card offers to put a name on your bug reports and playtest runs. It is optional, you can change it in Settings, and it doesn't have to be your real name.

### Internal

- Opt-in player name as a PlayerSettings text row, stamped on reports and runs (#1049, PR #1053). The launch notice became versioned, so installs that saw the old card are shown the new one.

## v0.190.2 (2026-09-20)

- Enemy threat marks were redrawn. They pulse from the enemy toward its target, point in a direction, and no longer look like your own aiming lines.
- The title screen tells you when a newer build is out, with a link to download it.

### Internal

- Threat mark direction, motion and vocabulary (#1042, PR #1048). A first-time player on stream read a threat line as another way of aiming a fireball.
- A placed blast spreads outward from where it lands and is stopped by walls and height (#805, PR #1047). No demo content authors a multi-cell placed blast yet, so nothing on these boards changes.
- Builds upload to itch with butler from archive-build.ps1, which then announces the version to the intake Worker's release row that the in-game update check reads (#1060, PRs #1063 and #1064).
